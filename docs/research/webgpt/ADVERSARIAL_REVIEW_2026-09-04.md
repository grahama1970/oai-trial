VERDICT: FAIL — The verifier accepts leaky, structurally corrupted, and wrongly mapped corpora; the publication path is not atomic or snapshot-safe; and the attached bundle omits the executable evidence needed to substantiate its Docker, security, scale, cost, and eight-hour claims.

TOP_3_WEAKNESSES:
1. `4-source.md` → `src/anonymization_trial/verification.py`: the “independent” verifier is global-presence/count based, reuses transformer functions, and accepts concrete invalid outputs. It accepts Alice’s and Bob’s pseudonyms swapped in a CSV, accepts a dropped source row when each subject still appears once, accepts a protected value moved or replaced when the global count is balanced, and misses a JSON value encoded as `"\u0041lice"`.
2. `4-source.md` → `src/anonymization_trial/pipeline.py`: verification is not bound to the bytes ultimately published. A staged file can be modified after `verify_corpus()` and before `_manifest_digest()`; the modified corpus is then hashed and published with `status="ready"`. `_publish()` also deletes the prior release before commit, writes `report.json` non-atomically, performs no durability fsyncs, and leaves staging inside the consumer-visible output tree.
3. `1-readme-submission-architecture.md`, `3-security.md`, and the ZIP contents: almost all supporting evidence is asserted rather than supplied. The archive contains only four Markdown bundles—no tests, `Dockerfile`, CLI, `pyproject.toml`, report schema, benchmark output, cost script/input, production SVG, Terraform, SAST receipt, Battle receipts, or `.git`. Meanwhile, the supplied implementation repeatedly materializes entire files, tables, match lists, and corpus text despite claiming bounded streaming and TB/PB readiness.

ISSUES:
1. Verifier admits wrong identities, missing records, and relocated protected values — severity: high. Location: `src/anonymization_trial/verification.py::verify_corpus`, `_searchable`, and `_verify_subject_level`. Global pseudonym presence does not prove that every source occurrence was replaced at the corresponding logical location. Concrete fix: independently enumerate source locations—text span, CSV row/column, JSON path, or SQLite table/primary-key/column—and require the expected pseudonym at each corresponding output location; compare row counts, array lengths, key order, table counts, and per-file protected-value locations rather than aggregate corpus counts.

2. JSON-escaped sensitive values bypass verification — severity: high. Location: `src/anonymization_trial/formats.py::iter_searchable_text` and `src/anonymization_trial/verification.py::verify_corpus`. The verifier scans serialized JSON text rather than decoded string values, so an output containing one expected pseudonym plus `"\u0041lice"` passes even though its decoded value is `Alice`. Concrete fix: independently parse output with duplicate-key rejection and strict-number handling, scan decoded keys and string values, and compare a typed JSON-path ledger against the source.

3. JSON number handling can publish invalid JSON — severity: high. Location: `src/anonymization_trial/formats.py::_transform_json`. Input `{"n":1e400}` becomes `{"n": Infinity}` because `json.loads` converts the exponent to an infinite float and `json.dumps` defaults to `allow_nan=True`; the current verifier publishes it as ready. Concrete fix: parse numbers as `Decimal` or preserve numeric tokens, reject non-finite results after parsing, serialize with `allow_nan=False`, define exact numeric equivalence, and independently reparse the result under the same strict contract.

4. Verified staging can be altered after verification and still become READY — severity: high. Location: `src/anonymization_trial/pipeline.py::run_pipeline`, between `verify_corpus`, `_manifest_digest`, and `_publish`. The verifier returns no digest-bound receipt; later code hashes whatever bytes happen to exist after verification. Concrete fix: have the verifier return a strict manifest containing per-file hashes and structural digests, seal the verified staging tree, recompare every verified hash immediately before publication, and bind the verification-manifest digest into `report.json`.

5. Report-last publication is neither atomic nor crash-durable — severity: high. Location: `src/anonymization_trial/pipeline.py::_publish`. The code deletes the previous output, renames the corpus, and calls `Path.write_text()` for the report; there is no temporary report, `fsync`, directory sync, rollback, or recovery journal. Concrete fix: acquire an output lock, invalidate the old readiness marker first, use versioned corpus directories or a rollback-capable old/new rename protocol, write the report to a same-directory temporary file, flush and fsync it, atomically `os.replace` it, fsync directories, and test power-loss states in fresh processes.

6. “Private” staging is inside the release mount and survives hard crashes — severity: high. Location: `src/anonymization_trial/pipeline.py::run_pipeline`, `tempfile.mkdtemp(dir=output_root, prefix=".staging-")`. A host-side reader can observe the staging directory, and `SIGKILL` or power loss bypasses the `finally` cleanup; there is no startup recovery for stale stages. Concrete fix: use an explicitly private work directory or volume when concurrent output readers are in scope; otherwise document the weaker trust assumption, enforce mode `0700`, use run ownership metadata, clean or quarantine stale stages at startup, and ensure stale stages can never be selected as release input.

7. Policy and source snapshots have exploitable TOCTOU windows — severity: high. Location: `src/anonymization_trial/pipeline.py::run_pipeline`, `_preflight`, `_source_digests`, and `src/anonymization_trial/formats.py::_snapshot_sqlite`. `policy.json` is read before its symlink check and hashed again after processing; source paths are reopened repeatedly, so a file can be swapped for transformation and restored before the final digest. New files or WAL state can also appear after inventory. Concrete fix: lstat and open policy with no-follow semantics before parsing, compile and hash the same frozen policy bytes, freeze the source corpus into an immutable run snapshot or retain verified file descriptors, inventory the complete file set and inode/device metadata, and bind a source-manifest digest into the report.

8. Protected/sensitive partial overlap is not implemented and can produce a READY protected-value violation — severity: high. Location: `src/anonymization_trial/policy.py::_check_overlap`. The code checks equality and containment only, not suffix-prefix intersection. A policy with sensitive `abcP`, protected `Person-`, and source `abcPerson-` is accepted; the name pseudonym begins with `Person-`, so the pipeline publishes changed protected bytes while the occurrence count remains one. Concrete fix: detect actual protected and sensitive spans in every logical value and reject any intersection; also perform conservative compile-time prefix/suffix conflict checks and test overlaps whose replacement recreates the protected count.

9. Match-equivalent rules can map the same text to different identities — severity: high. Location: `src/anonymization_trial/policy.py::compile_policy` and `src/anonymization_trial/matcher.py::_select`. Conflict detection keys only exact source strings, so case-insensitive `Alice` and `ALICE` assigned to different subjects are accepted and one identity wins by `rule_id`. Concrete fix: compile a normalized match-domain index and reject two rules whose accepted match sets intersect unless they resolve to the same canonical identity and replacement; document when sensitive/sensitive overlap is precedence versus policy ambiguity.

10. Pseudonym domains are too small and collision search is a denial-of-service path — severity: medium. Location: `src/anonymization_trial/pseudonyms.py::_render` and `build_replacements`. IPv4 has 253 candidates and phone has 10,000; “domain extension” is claimed but not implemented, and each exhausted identity can perform up to 100,000 hash attempts. Concrete fix: preflight the policy cardinality against each bounded domain, reject immediately when impossible, use a documented larger type-valid domain where permitted, cap total collision work, and benchmark the worst accepted policy.

11. Pseudonym scope does not enforce the documented linkage boundary — severity: medium. Location: `src/anonymization_trial/pseudonyms.py::SCOPE_ID`, `_digest`, and `docs/PRIVACY_CONTRACT.md`. `SCOPE_ID` is globally fixed to `trial-v1`, so separate tenants or corpora using the same subject ID produce the same token despite `allowed_linkage.across_tenants: false`. Concrete fix: make scope an authenticated policy/run input with a stable tenant/purpose/corpus identifier, include it in report and manifests, or remove the cross-tenant unlinkability claim.

12. The implementation is not bounded-memory or streaming — severity: high. Location: `formats.py::_transform_text`, `_transform_csv`, `_transform_sqlite`; `matcher.py::_Aho.scan`; `pipeline.py::_source_digests`, `_manifest_digest`; and `verification.py::_searchable`. These call `read_bytes`, `fetchall`, collect every raw match, or accumulate the entire corpus’s searchable text. Concrete fix: use incremental digests and UTF-8 decoding, bounded CSV lookahead, `fetchmany` for SQLite, a streaming leftmost-longest match frontier, streaming format-aware verification, policy/file/field bounds, output-expansion limits, and disk-space preflight.

13. CSV preservation claims exceed the implementation — severity: medium. Location: `src/anonymization_trial/formats.py::_detect_newline` and `_transform_csv`. Any CRLF causes one selected output terminator, CR-only input is changed to LF, mixed terminators are normalized, and the writer may change quoting; the verifier never reparses or compares row width/order. Concrete fix: define whether preservation is byte-level or logical, explicitly accept/reject dialects and mixed newline styles, retain the selected dialect contract, and independently compare headers, row counts, widths, cell order, and non-sensitive values.

14. SQLite row targeting and relational verification are incomplete — severity: high. Location: `src/anonymization_trial/formats.py::_transform_sqlite` and `_verify_sqlite`. Bare `rowid` may resolve to a user-declared column: a table with duplicate declared `rowid` values causes one update to overwrite multiple rows. Update triggers can also mutate unrelated values while row count, integrity, and foreign keys remain valid. Concrete fix: address rows by declared primary-key tuples; use hidden row IDs only after proving `rowid`, `_rowid_`, and `oid` are not shadowed; reject unsafe trigger/virtual/generated configurations in v1; and independently compare schema, indexes, triggers, row counts, key relationships, BLOBs, and all non-text values.

15. The readiness report does not bind the claimed evidence chain — severity: high. Location: `src/anonymization_trial/pipeline.py::RunReport` and `run_pipeline`. It has no schema identifier, run ID, source-manifest digest, compiled-plan digest, verification-receipt digest, or explicit check results. Its policy hash may describe policy bytes different from those compiled. Concrete fix: introduce a strict versioned report schema; populate it only from frozen policy/source/plan/verifier artifacts; include their hashes plus the exact corpus hash and code/image identity; validate the complete report before atomic publication.

16. Policy validation is not actually strict — severity: medium. Location: `src/anonymization_trial/policy.py::load_policy` and `compile_policy`. Missing `sensitive_values` and `protected_values` are accepted as empty arrays, `version: true` compares equal to `1`, duplicate JSON keys are accepted last-wins, and no limits exist for rule count, literal length, identity length, or data type. Concrete fix: use a duplicate-rejecting JSON loader and strict schema-equivalent validation with exact types, required fields, bounded sizes, a supported type vocabulary, and typed errors for malformed policy JSON.

17. Privacy-safe errors are a convention, not an enforced boundary — severity: medium. Location: `src/anonymization_trial/errors.py::AnonError`, `policy.py`, and `verification.py`. User-controlled `rule_id`, `data_type`, and filenames are interpolated into messages; a policy can place an email address in `rule_id` and trigger a duplicate/overlap error that leaks it. Concrete fix: validate externally visible identifiers against a safe grammar, render only error codes plus opaque path/rule digests, centralize exception conversion, and test stdout, stderr, reports, and receipts against all policy values and hostile identifier fields.

18. Re-identification non-claims are directionally good but internally inconsistent — severity: medium. Location: `docs/PRIVACY_CONTRACT.md`, `src/anonymization_trial/pipeline.py::_DOES_NOT_ESTABLISH`, and `pseudonyms.py`. The contract assumes the consumer lacks a private key, but the local construction has no private key; it is a public unkeyed SHA-256 namespace. It also labels occurrence replacement and structural preservation “proven” when the supplied verifier does not prove them. Concrete fix: assume the adversary knows the algorithm and public namespace, explicitly disclaim offline dictionary resistance and cross-corpus unlinkability, distinguish local public pseudonyms from production HMAC pseudonyms, and remove “proven” claims until location-aware verification passes.
