# Design Decisions and Limitations

Optional reviewer handout for the privacy-engineering trial. Each answer states the decision, its tradeoff, and where to inspect it. This is a navigation aid—not a new test report or an additional acceptance checklist.

## Questions at a glance

| Question | Short answer / tradeoff | Code or evidence |
|---|---|---|
| **1. Why use an explicit policy instead of automatically detecting personal data?** | The policy states which literals are sensitive, which values are protected, and which aliases share an identity. This makes the transformation obligations explicit and checkable. It does **not** establish that the policy finds all personal data or assigns real-world identities correctly. | [`compile_policy`](../src/anonymization_trial/policy.py); [matching semantics](ANONYMIZATION_SEMANTICS.md) |
| **2. Are the pseudonyms stable—and does that make the output anonymous?** | Declared aliases share a replacement; different identities of the same type receive distinct replacements or the run rejects. Allocation is deterministic for the same policy version, namespace, and identity set. The namespace is public and unkeyed: consistency is not cryptographic secrecy, and linkage resistance or formal anonymity is not established. | [`build_replacements` and `_digest`](../src/anonymization_trial/pseudonyms.py); [privacy contract](PRIVACY_CONTRACT.md) |
| **3. What happens when replacement rules conflict or overlap?** | Sensitive/protected conflicts reject rather than silently choosing one obligation. Among sensitive matches, selection is leftmost-longest with a stable rule-ID tie-break. Replacement uses original spans only; generated text is never rematched for replacement. Verification still scans it for residual sensitive literals and may reject the release. | [`compile_policy`](../src/anonymization_trial/policy.py); [`Matcher.replace` and `_select`](../src/anonymization_trial/matcher.py) |
| **4. What does “preserve the data” mean across four formats?** | Preserve the supported logical structure and values except for policy-authorized replacements—not identical serialization. CSV quoting, JSON formatting, and SQLite physical pages may change. Malformed data and unsupported features reject instead of being guessed at or silently discarded. | [format adapters](../src/anonymization_trial/formats.py); [supported semantics](ANONYMIZATION_SEMANTICS.md) |
| **5. Is the verifier genuinely independent?** | It rereads source and output and checks expected values, locations, types, file sets, and remaining sensitive literals. That catches errors such as a correct replacement on the wrong row. However, it shares replacement primitives with the transformer, so common-mode defects remain possible. Separate qualification readback provides another bounded check, not a fully independent engine. | [`verify_corpus` and `_typed_equal`](../src/anonymization_trial/verification.py); [qualification `readback`](../scripts/qualify_submission.py) |
| **6. Can a failed run leave output that looks ready?** | Consumers must require a valid `report.json` that binds the release; the directory alone is not readiness. Publication rechecks the verified corpus digest and writes the report last using a temporary file, `fsync`, and rename. This is not full rollback, a signed attestation, or an exhaustive power-loss guarantee; staging assumes a trusted single writer. | [`_publish`](../src/anonymization_trial/pipeline.py); [publication regression cases](../security/tests/test_publish_hardening.py) |
| **7. What do the security evaluations actually demonstrate?** | White-box source analysis, gray-box mutation cases, and black-box CLI checks examine different failure surfaces. Their scope is the exercised cases, not a universal security guarantee. The retained Judge demonstration is **fixture-backed**, not a live adaptive attack campaign against this target. | [security evidence and limits](../security/SECURITY.md); [adversarial matrix](../security/ADVERSARIAL_MATRIX.md); [Battle objective](../security/BATTLE_OBJECTIVE.md) |
| **8. Has this been shown to handle a petabyte within the proposed SLA?** | No. Small synthetic workloads were measured; TB/PB capacity and costs are modeled scenarios. The local adapters materialize files or tables, and verification retains searchable text from both corpora in memory; this is not bounded-memory streaming. Distributed processing, workload measurements, quota validation, and deployment would be needed to validate the cloud proposal. Reproducible arithmetic does not validate its assumptions. | [production design](production-architecture.md); [cost calculator](../scripts/estimate_aws_cost.py); [model inputs](../costs/aws-us-east-1-inputs.json); [verifier `_searchable`](../src/anonymization_trial/verification.py) |
| **9. Can fuzzy alias discovery silently change a release?** | No. Optional discovery proposes private, whole-value name candidates; similarity is not an identity probability. Explicit approval recomputes the review and compiles a new exact policy. Approval adds a **global literal rule**, not a location-only edit, and does not mark a corpus ready. The normal pipeline must still run. Canonical destination checks keep private review and approval artifacts outside releases. | [discovery contract](DISCOVERY.md); [`discover` and `approve`](../src/anonymization_trial/discovery.py); [`separate_output`](../src/anonymization_trial/bundle.py); [boundary regression](../tests/test_discovery_boundaries.py) |
| **10. Was everything completed within the eight-hour trial?** | No verified under-eight-hour completion is claimed. The recorded work-commit span exceeded eight hours; active engineering time was not tracked separately. Post-timebox corrections and subsequent additions are disclosed. The retrospective allocation is an estimate, not proof of timebox compliance. | [time-spent disclosure](../SUBMISSION.md#time-spent) |

## Research and reuse

The [research and reuse map](pitch/oai-trial/reorganized/sources/research-workflow.md) explains the development workflow: frame the problem, search current research and implementations with `$dogpile`, inspect existing projects and skills, then compose suitable components before writing custom contract logic. It distinguishes adopted ideas from rejected options and design-only proposals.

## Reading the evidence

- **Code links** identify the mechanism; **test links** identify retained cases, not a fresh execution result.
- **Cloud figures** are models. **Judge results** are fixture-backed. Neither should be presented as live production evidence.
- Use this table to choose a code discussion. The longer presentation question bank remains preparation material, not a list the reviewer needs to work through.
